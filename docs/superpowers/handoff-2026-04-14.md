## Gotchas for the resuming session

1. **The user already approved the spec and plan.** Do not re-run
   brainstorming or re-present design sections. Those skills have already
   been invoked and closed out.
2. **Korean is the user's default.** They can switch to English on request,
   but default to Korean for conversational responses.
3. **The user prefers terse responses.** Don't write long explanations when
   a short one will do. The brainstorming phase was verbose by necessity;
   implementation chat should be leaner.
4. **Commits are welcome but pushes need judgment.** The user has been
   explicit about wanting commits along the way. They do say "푸시" or
   "커밋해줘" when they want remote publication — when unclear, confirm.
5. **The `Aegis-MCP` repo name is locked in for URL stability.** The Python
   package is `aegis` though. Don't rename the repo.
6. **Security/governance is explicitly out of scope.** Do not reintroduce
   MAC, PII masking, audit logs, multi-user auth, etc., even when "it seems
   useful". These are in the spec's §2 non-goals.
7. **Dogfooding over benchmarks.** The user chose not to build a benchmark
   harness. Do not propose one. Section 6 of the brainstorming Q&A was
   explicit: "dogfooding is sufficient proof".
8. **Time is unlimited, but scope isn't.** The "unlimited tokens" signal
   means go deep on quality within each phase. It does NOT mean "add more
   features beyond the spec". Stick to the approved §2 non-goals.
9. **Git worktrees are the isolation mechanism for agents** (spec §11.4).
   This is already validated and should not be reopened.
10. **The CLI framework is Typer** (plan Task 8 uses it). Python 3.11+. Do
    not swap to Click or Fire mid-implementation.
11. **Budget tracker subtlety (plan Task 6):** `BudgetTracker` uses
    `__post_init__` instead of `field(default_factory=monotonic)` so that
    `monkeypatch.setattr("aegis.core.budget.monotonic", ...)` works in
    tests. Do not "simplify" this back.
